# 角色设计与展示素材

用于决定新角色主题长什么样，以及在用户需要时制作 README 截图和展示短片。
本仓库的灰原哀实现是可检查的案例；冷紫、银箔、漫画、胶囊和八种展示形式都不是通用要求。
下文 `src/`、`docs/` 路径均相对于主题仓库根目录；移植时以目标仓库实际结构为准。

## 先提炼角色，再选择表现形式

从用户提供的角色、素材和用途提取一份短设计说明：

| 决策 | 需要落到具体内容 |
| --- | --- |
| 角色气质 | 选少数相互协调的词，并解释如何影响颜色、形状、排版或运动 |
| 识别线索 | 服饰、物件、轮廓、姿态、代表性色彩；挑出适合小尺寸的线索 |
| 图像语言 | 摄影、插画、像素、剪纸、漫画或其他形式；跟随素材和用户选择 |
| 工作台观感 | 装饰出现在哪里，正文和操作区保留多大留白 |
| 动态语言 | 缓慢呼吸、短促弹性、纸片滑入等；没有合适依据时保持静态 |

将“角色很冷静”转成可执行选择，例如低饱和背景、克制重音、较小运动幅度；不要只留下形容词。
避免把角色的全部代表色同时用于控件，也不要把所有页面变成角色海报。
先用真实标题、长会话、设置控件和实际图片做一个代表页面，再扩展其他位置。
用户已经确定方向时直接沿用；只有角色身份、可用素材或核心用途缺失且影响结果时才补问。

可复用的设计提示词：

> 为 [角色/原创人物] 设计 DeepSeek Harness 工作台主题。依据 [素材与来源]，提炼角色的视觉线索，并分别落到明暗配色、装饰构图、字标和可选动效。正文、编辑器和控件以持续使用的清晰度为先。用 [指定风格，未指定则根据素材判断] 呈现，说明每项选择的用途，先展示一个真实工作台页面和关键状态。

## 配色按语义成对设计

`src/palette.mjs` 展示官方语义 token 的 light/dark 配对方式；复用结构，重新设计色值。
先确定底色、浮层、正文、次要文字、边框、品牌重音，再处理 hover、selected、disabled 和业务状态。
浅色与深色应各自建立层次，不能简单反相；同一人物素材在两种底色上可能需要不同边缘或衬底。
品牌色适合选中态和主操作，成功、警告、错误仍需保持各自可理解的状态差异。
用真实组件验证以下组合，而不只检查色板：

- 主按钮的文字与填充、键盘焦点、按下或悬停状态。
- 侧栏未选中项、当前项和会话未读标记。
- 正文、链接、引用、代码块、输入框、提示框与浮层。
- 禁用控件与次要说明，及主题关闭后的恢复效果。

检查对比度时使用最终叠加后的颜色；半透明纹理和装饰图片也会影响可读性。
普通文字以至少 4.5:1、大字至少 3:1、关键控件边界和焦点至少 3:1 作为检查目标。
不要为“全站统一角色色”把正文、错误状态、原生控件全部覆写成一个色系。
跨插件颜色通过官方语义变量传递，不把特定角色图片或固定色值写入业务插件。

## 素材承担角色，不按数量凑图

先列素材清单，记录来源、作者或权利方、可用范围、原尺寸、裁切和加工内容。
现有仓库的角色图片不因代码采用 MIT 就获得相同许可；新主题使用自己有权使用的素材，并保留相应说明。
素材不足时可以用少量图、纯配色和原创标志完成主题，不必复制示例图片或搜索凑齐八张。
如用户授权生成新图，使用可用的生成工具；不把某个付费服务设为必要条件。
人物摄影保持合理肤色和主体比例；像素素材明确缩放策略；插画保留线条、透明边缘与作者署名要求。

| 展示角色 | 选图与布局判断 |
| --- | --- |
| 首页主视觉 | 轮廓清楚，人物朝向与标题关系成立，可在窄屏缩小或隐藏 |
| 页头小图 | 横向或可安全裁切；面部、手部与关键物件不被边框切断 |
| 侧栏装饰 | 小尺寸仍可辨认，避开会话列表、底部按钮及滚动路径 |
| 空状态 | 配合说明与主要操作；只在实际空状态出现 |
| 品牌标志 | 在浏览器标签和导航的小尺寸下也能辨认，可独立于人物图存在 |

`src/theme-artwork.tsx` 管理 variant 与实际图片，`src/theme-definition.mjs` 把中性位置映射到 variant。
复用一个 variant 到多个位置可以成立，但每个位置需验证尺寸、裁切和可用留白。
素材少时同步精简 `ARTWORK_VARIANTS`、图片映射、角色映射、图库、设置中的直接引用和翻译键。
删除 variant 后检查设置预览、首页特例、CSS、测试及文档，避免图库仍展示不存在的选项。
变体名描述构图用途即可，不必继承 `silver-*`、`manga` 或角色专有名称。
强度设置只有在每档可看出合理差异时才保留；差异可来自透明度、衬底或纹理，不应导致正文失读。

装饰放入专用出口，默认 `pointer-events: none`、`aria-hidden="true"`；仅真正需要交互的自有文字盒接收指针。
标题、上传按钮、编辑器、菜单和滚动区域优先；空间不足时缩小或隐藏装饰，不压缩业务内容硬塞进去。
`docs/appearance-contract.md` 中的位置是语义协议；不要根据插件名称、会话内容或用户文件选择角色图。
明暗、无装饰、窄宽度、短窗口、长标题都要实看；关闭装饰后不留下空白占位。

## 字标要有字体与构图依据

把品牌名称、连接词、英文重音、角色签名和正文区分开；表现力来自字体、大小、字重、留白与对齐的组合。
角色名可以成为视觉重点，辅助文字保持克制；不要用“随便换个楷体”代替排版设计。
只为品牌字样选择展示字体；正文和功能控件继续使用适合阅读的宿主字体。
`src/brand-fonts.css` 当前是固定文字子集，不能因为字体家族名支持中文就假定包内覆盖新角色名称。
新增 CJK、英文大小写、标点和本地化文本后，核对实际字形覆盖、字重、斜体与缺字回退。
若沿用 `scripts/fetch-brand-fonts.py`，先修改其明确的文案输入，再同步字体文件、Unicode 范围与来源记录。
也可选择合法可分发且覆盖完整的本地字体；保留许可证，并避免让运行时依赖外部字体服务。
用最终品牌文字做截图比较，检查中文与 Latin 的基线、视觉字号及窄屏换行。
`src/theme-artwork.tsx` 的字标拆段只针对现有品牌文案；新文案重新判断语义与读屏名称，不做全局字符串替换。

## 产品动画以可停、可读为前提

先选一个有角色依据的动作：例如标志显现、签名描线或少量视差；不要同时让全部素材循环运动。
`src/title-motion.mjs` 与 `src/artwork-projection.mjs` 可参考字体就绪、指针条件和清理机制。
新增或保留动画时，同时尊重系统 `prefers-reduced-motion` 和产品“减少动态效果”选项。
触屏、失焦、页面隐藏、无装饰和卸载时恢复静态；停留状态不持续运行无意义的绘制循环。
标题轮廓动画必须等字体与尺寸就绪，原文和无障碍名称仍完整；失败时显示可读静态文本。
鼠标交互不要覆盖点击、文本选择或键盘操作，也不要让相邻业务组件跟随人物位移。
对照片和像素风使用适合原素材的运动；不为套用案例强制添加漫画分层或银箔闪动。

## 真实截图：先决定每张说明什么

用户需要展示资料时，先列每张图的用途；合理起点是首页、同构图明暗对照、设置和另一处有区别的场景。
若主题没有某功能就不拍对应图；无装饰对照、局部字标或独立标志按内容价值添加。
使用正在运行的已核验版本和独立测试数据，记录主题版本、宿主版本、视口和启用的其他插件。
保持明暗对照的尺寸、内容和滚动位置一致，等字体与图片加载完成后再截图。
使用正常授权的浏览器连接，不将带认证信息的 URL、真实聊天、用户名或密钥录入素材。
组合安装时标明组合效果，避免把导航或其他插件功能归为主题自身能力。
保留原始截图；裁切、标注和封面排版另存，不能用绘制界面替代真实功能证据。
逐张实看主体、边缘、控件文字和空白比例，再决定 README 的首图与排序。

## 可选展示短片：产品画面与后期分开

仅在用户需要视频或宣传素材时执行；主题 Skill 不要求每次制作视频，也不默认发布任何产物。
先确定用途、宽高比、时长范围、声音需求和已有素材；展示短片可以有气氛，操作演示要让步骤可辨认。
分镜写明“画面来源、时长、观众看到的变化、字幕、转场”，一个镜头只强调一个重点。
以已完成主题的真实截图、录屏和可用角色原素材为基础；真实设置或交互能力用真实操作体现。
可选的后期手法包括构图匹配、形状遮罩、明暗擦拭、素材分层、局部推近和字幕字形揭示。
从角色自己的识别物件选转场线索，不把胶囊、紫色、银箔或固定 38 秒当成模板要求。
后期透视、爆炸分层、人物退场和遮罩转场属于视频编排，不能暗示产品本身具有这些动画。
对容易混淆的镜头加“主题展示 / 后期演绎”等说明，或以清楚的画面风格区分。
文案可短而有性格；主副字形成层次，静音观看仍能理解，字幕不覆盖关键控件。
声音使用可授权的音乐和音效，来源写入工程记录；无合适素材时可保持静音。
优先使用环境里已有的录制与剪辑工具；可以用浏览器录制、程序化合成和 FFmpeg，不强制某一工具栈。
逐镜检查后完整播放成片，检查缺帧、黑帧、裁切、字幕时长、音量与结尾停留。
交付视频、封面与可再编辑工程，说明所用产品版本，以及哪些画面是后期效果。
上传仓库、发布页面或公开视频需在用户授权的范围内进行，不从“制作素材”推导发布权限。

可复用的短片提示词：

> 使用 [主题版本] 的真实截图、录屏与 [已可用素材]，为 [角色主题] 制作 [用途、比例、时长范围] 的展示短片。以 [角色视觉线索] 组织镜头，依次让观众理解 [核心亮点]。每镜写清来源、字幕、观察时间和转场。后期可以使用 [适合该角色的手法]，真实产品交互保持真实；明确区分后期演绎。保持界面文字清晰、字幕有主次，输出可播放成片、封面与可编辑工程，按 [已确认声音偏好] 处理声音。
